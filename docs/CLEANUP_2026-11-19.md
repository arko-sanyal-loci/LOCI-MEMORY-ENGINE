# Cleanup pass, 2026-11-19

A start-to-finish pass over this repository for redundant, broken or misconfigured code. Every
change below lists the evidence that justified it. Test suite before: 129 run by CI (unittest
discovery), 171 collected by pytest with 1 failing. After: **228 passed, 8 skipped** (the 8 need
a live Ollama server and skip themselves when it is not reachable; they were written that way).

## Bugs fixed

| # | Problem | Evidence | Fix |
|---|---|---|---|
| 1 | **The MCP server and HTTP bridge could not start.** `mcp_server.py` and `sovereign_bridge.py` import `route_inference` and `OLLAMA_ENDPOINTS` from `gpu_governor`, but `finalize_station0.sh` had replaced that module with a copy that dropped both. | `python -c "import loci_engine.mcp_server"` raised `ImportError: cannot import name 'route_inference'`. The removed code was still in `gpu_governor.py.stale-vulkan-20261104_224204.bak`. | Restored `route_inference()` and `OLLAMA_ENDPOINTS` (endpoints now overridable with `LOCI_NVIDIA_ENDPOINT` / `LOCI_ARC_ENDPOINT`, since the Arc lane moved to llama.cpp SYCL). New `tests/test_gpu_governor.py`. |
| 2 | **`node_sync.sh` would reset every deployed node on every run.** It compares `origin/main:manifest.sha256` with a hash of `loci_engine/`. The manifest was last written 2026-11-01 and the engine changed many times since; the hash also counted `__pycache__` files, which importing the engine creates and `git clean -fd` does not remove. | Recomputed hash `9e7a0fe5…` vs recorded `8eb8cbf8…`. `check_remote_parity.sh` already excluded bytecode; `node_sync.sh` did not. | One hash definition in `scripts/ops/engine_hash.sh`, used by `node_sync.sh`, `check_remote_parity.sh` and the new `scripts/ops/update_manifest.sh`. Manifest regenerated. `tests/test_manifest.py` fails whenever it goes stale. |
| 3 | **The RAG pipeline could not import.** `rag/pipeline.py` imported `loci_engine.vectors`, which exists only in the legacy `loci-memory-engine-1` repo. | `ModuleNotFoundError: No module named 'loci_engine.vectors'`. | Ported it as `rag/vector_store.py` with its own chunk-heat helpers (`rag/chunk_heat.py`), unchanged in behaviour. Ported the 9 RAG test files to `tests/rag/`. |
| 4 | **The coordination-bus MCP test failed.** The code imports `mcp.server.fastmcp`, which `mcp` 2.x renamed. The pin lived in the old bus repo's `pyproject.toml` and was lost in the merge. | Installing current `mcp` (2.x) raised the rename error; `mcp<2` passes. | `pyproject.toml` pins `mcp>=1.2,<2`. |
| 5 | **`pip install -e .` did not work**, though the README told users to run it. There was no `pyproject.toml`. CI hid this with `... 2>/dev/null \|\| true`. | `ls pyproject.toml` → missing. | Added `pyproject.toml` with extras `mcp`, `bridge`, `rag`, `dev`. CI installs with no fallbacks. |
| 6 | **CI skipped 42 tests.** `python -m unittest discover` does not collect pytest-style tests in `tests/coordination_bus/`. | unittest ran 129, pytest collected 171. | CI runs `python -m pytest -q`. Dropped the `reconcile` push trigger. |
| 7 | **The default database path failed on a fresh machine.** `StorageEngine()` defaults to `~/loci-memory-engine/context2.db` and never created the folder, so `mcp_server` crashed at import with `unable to open database file`. | Reproduced with an empty `$HOME`. | `StorageEngine` creates the parent folder. |
| 8 | **The README's Python example did not run.** It imported `LociCore`, which does not exist, and listed MCP tools that are not there. | `ImportError: cannot import name 'LociCore'`. | Rewrote the examples against the real API and ran each one. New `docs/USER_GUIDE.md`. |

New guard: `tests/test_imports.py` imports every module in `loci_engine`, `coordination_bus` and
`rag`, so a missing module fails CI instead of failing on a user's machine.
